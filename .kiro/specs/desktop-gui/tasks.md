# Implementation Plan

> 順序が依存を表す(タスク N は先行タスクに依存する)。`(P)` は直前の並列候補と競合しない独立タスク。依存の例外は `_Depends:_` で明示する。上流の `brainfuck-core` / `debugger-state` / `brainfuck-cli` が実装済みであること(`cargo test --workspace` が成功する状態)を前提とする。特に `debugger-state` が `brainfuck_core` のルートから公開する `SourceMap::position_at`、`SourceMap::instruction_at_or_after_utf16`、`tape_window_of`(および `DebugSession::tape_window`)が利用可能であることを前提とし、本 spec はこれらを呼ぶのみで位置・逆引き・窓の計算を実装しない。

- [ ] 1. 基盤: クレート・アプリ・型生成・テスト基盤の用意

- [x] 1.1 Tauri 非依存の API クレートの骨格を用意する
  - 新規ライブラリクレートをワークスペースに追加する(ルートの `members = ["crates/*"]` により自動参加。ルートの設定ファイルは変更しない)。本番依存は `brainfuck-core`、`serde`、`base64`、`ts-rs` のみ。テスト用の開発依存(`serde_json` と一時ディレクトリ補助)を追加する。`unsafe` を禁止し、ワークスペースの lint を継承する
  - 以降のタスクが同一ファイルを奪い合わないよう、全モジュール(制限値・コーデック・DTO・変換・サービス・ファイル補助)の宣言と空ファイルを先に用意する。変換モジュールは公開モジュールとし、後続の比較画面が再利用できるようにする
  - 制限値(ソース/入力 1 MiB、バッチ幅上限 1,000,000、窓半径上限 64、出力末尾 65,536、命令数上限の上限 2^53−1、既定上限 10,000,000、ブレークポイント配列上限 100,000)を定数として定義する
  - Base64 のエンコード/デコードを、復号前に長さで上限検査するコーデックとして実装する(コーデックは DTO より前の層のため、独自のエラー型を返し、サービスが構造化エラーへ写す)。往復・不正文字・上限超過の単体テストを書く
  - 完了条件: `cargo test --workspace` が(フロントのビルド成果物なしで)成功し、コーデックのテストが通る
  - _Boundary: limits, codec_
  - _Requirements: 13.6, 13.8, 15.5_

- [x] 1.2 共通 DTO と TypeScript 型の生成基盤を用意する
  - 位置(バイト・UTF-16・行・列)、範囲、解析エラー、実行エラー(ポインタ範囲外/命令数上限超過)、出力チャンク、API エラー(種類・固定文面・項目名)の DTO を定義する。JSON は camelCase、判別付き列挙は `kind`、`u64` は `number` として出力する
  - DTO から TypeScript 型を生成してアプリのフロントの生成物置き場へ書き出す手段(手動更新用の実行例)を用意し、生成物をコミットする
  - 「新規生成結果とコミット済みの生成物が一致する」ことを検査するテストを追加し、不一致時に更新手順を表示する
  - 完了条件: 生成された型ファイルがリポジトリに存在し、生成物を手編集すると一致テストが失敗する
  - _Boundary: dto, bindings tooling_
  - _Requirements: 12.6, 12.7, 12.10, 12.13_

- [x] 1.3 セッション・実行・ブレークポイントの DTO を定義する
  - ソース読み込みの結果(成功/解析エラー)、セッション開始(入力・命令数上限(上限あり/なし)・ブレークポイント位置・表示要求)、バッチ実行、Step、リセット、現在状態、テープ窓、ブレークポイント(解決済み位置と未解決位置)、Pause の要求/応答 DTO を定義する
  - バッチの停止(正常終了・ブレークポイント・キャンセル・バッチ到達・実行エラー)と直近の停止理由を、互いに区別できる判別付き表現にする
  - 状態の応答にスナップショット、テープ窓、現在命令の範囲、入力の読み取り済み/総数、直近の停止理由、出力の差分(開始位置・総バイト数・Base64)を含める
  - ファイル操作の DTO(開く結果: 開いた/取消、保存の要求: ソースと別名指定、保存結果: 保存した/取消、未保存フラグの要求)も定義し、Tauri 層とフロントが同じ生成型を使えるようにする
  - 完了条件: 全 DTO が JSON で往復でき、生成した TypeScript 型が最新で一致テストが通る
  - _Depends: 1.2_
  - _Boundary: dto_
  - _Requirements: 2.5, 2.8, 12.1, 12.2, 12.3, 12.4, 12.5, 12.8, 12.9_

- [ ] 1.4 フロントエンドの骨格とテスト基盤を用意する

  - フロントで共有する制限値の定数モジュール(ソース/入力 1 MiB、出力保持 65,536、命令数上限の上限 2^53−1、窓半径上限 64、バッチ幅の下限/上限)を用意する(ts-rs は定数を出力しないため。Rust 側の値と一致することは 9.1 の契約テストの値と手で突き合わせる)。3.x・5.x・7.x はこれを import し、各自で数値を再定義しない
  - `.gitignore` に `node_modules` / ビルド成果物 / Tauri のビルド出力を追記する(既存行は変更しない)
  - 完了条件: 型検査・lint・Vitest が空に近い状態で成功し、サンプル取り込みのテストが通る

- [ ] 1.5 Tauri アプリの骨格と最小権限の設定を用意する
  - 独立ワークスペースとしてアプリのシェル(Tauri 2)を作成し、API クレートへパス依存する。ウィンドウ(最小 800 × 600)、CSP(自己オリジンのみ、外部通信なし、スタイルはインライン許可)、`withGlobalTauri` 無効を設定する
  - アプリのコマンド一覧を 1 か所(コマンドモジュールの登録一覧)にまとめ、ビルド設定でコマンドごとの権限を生成する構成にする。ケイパビリティはイベント権限と自アプリのコマンド許可のみとする
  - ダイアログ用プラグインを Rust 側にのみ登録し、WebView にはプラグイン権限を与えない
  - ビルドに必要なアプリアイコンと、フロントのビルド出力先の仮ディレクトリ(コンパイル時に存在が要求される)を用意し、開発起動/ビルドのコマンドが 1.4 のスクリプトを呼ぶよう設定する
  - アプリは独立した `[workspace]` でありルートの `[workspace.lints]` を継承できないため、アプリ側の `Cargo.toml` に `[lints.rust] unsafe_code = "forbid"` を自前で宣言する。tauri のマクロ展開が `forbid` と衝突しないかをこの時点で `cargo check` により確認し、衝突する場合に限り `deny` へ落として、その事実と理由をアプリ側 `Cargo.toml` のコメントに残す(9.5 が README の検証記録へ転記する。アプリ側ソースに `unsafe` は書かない)
  - アプリ側の `Cargo.lock` はアプリ専用のものをコミットする方針とし、`serde` / `ts-rs` の解決バージョンをルートの `Cargo.lock` と同一に固定する(アプリ側の `Cargo.lock` をルートの `Cargo.lock` から種として作成するか、`serde` / `ts-rs` を `=` 指定の直接依存として宣言する。一致の確認は 9.6 の手順に含める)
  - 完了条件: コマンド未実装のままでも `cargo check`(アプリ側)が通り、ケイパビリティにファイル/シェル/HTTP/ダイアログの WebView 権限が含まれていない。アプリ側の `Cargo.toml` に `unsafe_code` の lint 宣言(`forbid`、または記録済みの理由つき `deny`)があり、アプリ側の `Cargo.lock` が存在して `serde` / `ts-rs` のバージョンがルートと一致する
  - _Depends: 1.1, 1.4_
  - _Boundary: apps/desktop src-tauri scaffold_
  - _Requirements: 12.14, 13.3, 13.5, 13.8, 14.5_

  - 解析エラー(種類・命令添字・括弧位置)を DTO へ写す公開関数を用意する(公開関数名は `source_position_dto` / `source_range_dto` / `parse_error_dto(source, error) -> Result<ParseErrorDto, ApiError>`。テストは `positions` テストファイルに置く)。位置は `SourceMap::position_at(source, バイトオフセット)` の結果を写し、取得できない場合は内部エラーにする。行・列・UTF-16 の数え方や UTF-16 の始点表・二分探索はここにも他のモジュールにも実装しない
  - 完了条件: ASCII・`あ`・`😀`・3 種の改行を含むソースで、全命令の `range_of` の結果と解析エラーの位置が、上流の値と同じフィールド値の DTO になるテストが通る(位置規則そのものの一貫性は `debugger-state` 側のテストが保証するため再検証しない)。ソース末尾の括弧不整合(末尾位置)も DTO になる

  - 表示用のファイル名(ディレクトリを含まない名前)を取り出す。エラー文面にパスや内容を含めない
  - 完了条件: 不正 UTF-8、1 MiB ちょうど/超、3 種の改行コードの往復、ディレクトリ非含有の表示名がテストで確認できる

  - ソース読み込み(上限検査 → 解析 → 解析エラーに位置付与、成功時は `SourceMap` を構築し新しいプログラム ID を採番、既存セッションを破棄)を実装する。サービスは `Mutex` の外に現在のセッション ID を保持するロック不要の原子的な値(0 = セッションなし)を持ち、セッションの開始・置換・破棄のたびに `Mutex` 保持中に更新する(2.6 の Pause が照合に使う)
  - セッション開始(プログラム ID の照合、入力デコードと上限検査、命令数上限の有無の反映、ブレークポイント位置の正規化と設定、新しいセッション ID の採番、初期状態の返却)を実装する。1 つのサービスは 1 プログラム・1 セッションのみを保持する
  - ブレークポイント位置の正規化(UTF-16 位置 → 命令添字は `SourceMap::instruction_at_or_after_utf16` を呼ぶ。重複は 1 件、命令が無い位置は未解決)をここで共通部品として実装し、後続のブレークポイント置換でも再利用する
  - 以降のサービス/一致テストが共有するテストヘルパ(サービス生成、ソース/入力の用意、バッチ反復、コア基準の実行)を用意する
  - 不正な値(上限超過のソース/入力、範囲外の上限・半径、古いプログラム ID)を構造化エラーで拒否し、状態を変更しない
  - 完了条件: 解析エラー・成功・古い ID・過大入力・命令数上限の有無の各ケースがテストで確認でき、サービスが `Send + Sync` であることがコンパイル時に検証される
  - _Depends: 2.3_

  - モード切替(テキスト→16 進は常に成功、16 進→テキストは UTF-8 として正しい場合のみ)と、総バイト数の算出、Base64 変換を実装する
  - 完了条件: 全角文字・0x00/0xFF・空白混在・奇数桁・不正文字・1 MiB 境界・不可逆な切替拒否の単体テストが通る

  - 完了条件: UTF-8 文字が 2 チャンクにまたがる場合に欠損しない、不正バイトが置換される、省略時に総バイト数が正確、空出力の表示、非 UTF-8 バイトがバイト単位で保持される、が単体テストで確認できる
