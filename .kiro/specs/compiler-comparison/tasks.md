# Implementation Plan

> 順序が依存を表す(タスク N は先行タスクに依存する)。`(P)` は直前の並列候補と競合しない独立タスク。依存の例外は `_Depends:_` で明示する。`_Depends:_` の数値は本計画内のタスク、`brainfuck-core` / `optimized-interpreter` / `desktop-gui` の語は当該上流 spec の実装済みを指す。
>
> **上流依存の二層構造**
> - **タスク 1〜3(WASM バックエンドと比較クレート)** が前提とする上流は `brainfuck-core`(既存の公開 API)と `optimized-interpreter`(公開の再生モジュールと、操作の素朴換算コスト・到達範囲のヘルパを含む)**のみ**(例外: 共有サンプル `examples/hello.bf` を読み込むテストを持つタスク 2.5・2.6・3.3 に限り、そのファイルを用意する `brainfuck-cli` のタスクが済んでいること。サンプルのコピーは作らない)。`desktop-gui` / `debugger-state` の実装前に着手・完了できる(`cargo test --workspace` はこの時点で成功する)。
> - **タスク 4〜7(比較 API クレート、Tauri 層、フロントエンド、文書・統合)** は `desktop-gui`(`debugger-state` を含む。デバッガ API クレートの公開部品、画面レジストリ、共有ワークスペースの値の型、共有の通信ヘルパ、生成型の運用)が実装済みであることを前提とする。
> - デバッガ API クレートは本計画では**一切変更しない**。再利用に必要な公開項目が欠けていた場合は、タスク 4.1 で記録して進行を止め、`desktop-gui` 側の対応を待つ。

- [x] 2.2 (P) 制限つきの隔離実行(ランタイム境界)を実装する

  - ホスト側に定義する関数は入力取得と出力送出の 2 つのみ。入力取得は未読バイトがあれば 1 バイトを返し位置を進め、尽きていれば 0 を返し位置を進めない。出力送出は上限を超える場合に実行を中断する
  - メモリの成長を拒否する制限(1 ページ固定)と、燃料(`上限 × 倍率 + 下駄`)による実行量の監視を設定する。実行後に戻り値(状態コード、`pc`、`dp`、実行数)、テープ先頭 30,000 バイト、入力位置、出力を取り出す。エンジンの型はこのモジュールの外へ出さない

- [x] 2.3 コード生成: モジュール骨格と直線的な操作(加減算・移動・入出力)を実装する
  - 最適化 IR から、型・import・1 ページのメモリ・実行関数・export から成るモジュールを決定的に生成する。実行関数は上限を受け取り、状態コード・`pc`・`dp`・実行数を返す。全体を離脱先のブロックで包み、操作のない(空の)プログラムは初期状態のまま停止を返す
  - 加減算・同方向移動・出力・入力を、設計の生成規則どおりに生成する: コストが残り予算を超える、または移動が範囲外に出る場合は、状態を変更する前に操作の先頭の命令添字を設定して離脱する。適用時は 8 ビットへのラップ、入出力は取り決めた 2 関数の呼び出しで行い、実行数に素朴換算コストを加算する。コストと到達範囲の定数は、上流が公開するコスト・到達範囲のヘルパを呼んで得る(式を独自に定義しない)
  - 直線的でない操作(ループ、クリア、移動/加算/乗算、走査)と未知の操作種別は、この時点から「常に離脱(状態コード = 離脱、`pc` = 操作の先頭の命令添字)」として生成する。以降のタスクは種別ごとにこの既定を置き換える
  - 構造テストを書く: 生成物が検証と監査を通る、同一 IR から同一バイト列、空プログラム、直線的な操作の全種を含むプログラムの生成。公開窓口の実装前なので、これらはコード生成モジュール内のテスト専用モジュールに置き、2.4 以降は公開のコンパイル窓口経由の構造テスト(統合テストファイル)へ拡張する
  - 完了条件: 直線的な操作のみのプログラムの生成物が検証・監査を通り、構造テストが成功する

  - _Boundary: emit_
  - _Requirements: 1.6, 1.9, 2.2, 2.4, 3.1, 3.6, 4.1, 4.2, 6.1, 6.2, 6.5_

- [x] 2.4 コンパイル/実行の公開窓口と、離脱後の再生の接続を実装する
  - 生成 → 監査 → ロードを行う「コンパイル」(外部供給のモジュールを受け取る入口は作らない)と、実行 → 離脱時の再生 → 結果確定を行う「実行」を実装する。実行結果は、結果、`pc`、`dp`、素朴換算の実行数、入力位置、出力、テープ全体、離脱の有無、ホスト再生の命令数を持つ。成果物のバイト数を参照できる
  - 離脱時は、実行エンジンから取り出した途中状態(線形メモリのテープ、`dp`、実行数、入力位置、出力と呼び出し元の入力)を、上流が公開する再生の状態へ詰めて渡し、再生を進め、状態を読み戻して結果を確定する。素朴意味論の再生は自前で実装しない。再生状態の生成が拒否された場合(不整合な途中状態)は、拒否の理由をすべて専用の実行失敗として返し、素朴のエラーに偽装せず panic しない。離脱がなければ再生を呼ばず、離脱なしの結果は離脱の有無が偽・ホスト再生の命令数が 0 になる。再生後は生成コードへ戻らない
  - コンパイルとモジュール再利用は、異なる入力・上限での複数回実行が互いに独立であること(空プログラム、直線的な操作の数本で確認する)
  - 不整合な途中状態(`dp` が範囲外、テープ長の不足、入力位置が入力長を超える)を手組みで与えると専用の実行失敗になり panic しないことを、窓口モジュール内のテスト専用モジュールで確認する
  - 完了条件: 上記テストが成功し、直線的な操作の簡単なプログラムが公開窓口経由で実行でき、離脱なしで正しい結果を返す
  - _Depends: 2.1, 2.2, 2.3, optimized-interpreter_
  - _Boundary: WasmProgram_
  - _Requirements: 1.3, 1.9, 2.1, 2.3, 2.4, 3.2, 3.3, 5.1, 5.5, 8.6_

  - ループ開始/終了を、セル 0 での脱出とセル非 0 での先頭への分岐、各 1 命令の素朴換算コスト(予算不足なら離脱)で生成する。ループは入れ子の構造化制御として表す

  - 完了条件: 一般ループを含むプログラムで核との一致テストが成功し、制限超過が未対応として分類される

- [x] 2.7 コード生成: クリアと移動/加算/乗算ループを実装する
  - クリア(`[-]` `[+]`)と移動/加算/乗算ループを、設計の閉形式コスト(クリア: セル値に応じた 1+2v(`[+]` は 1+2(256-v))、乗算: セル 0 なら 1、そうでなければ 1+v(本体長+1))と範囲条件(セル非 0 のとき到達範囲が `dp` に対してテープ内)に従って生成する。セル値に依存しない定数(本体長、到達範囲)は上流のヘルパから得る。コスト超過・範囲外となりうる場合は状態を変更せず離脱する。2.3 の「常に離脱」の既定をこれらの種別について置き換える
  - テストを書く: セル値 0, 1, 2, 127, 128, 255 のクリアと乗算が核と完全一致する、生成コードの実行数が上流のコストヘルパの値と一致する、上限掃引(操作の途中の上限を含む)で一致する、乗算ループが範囲外に触れうるがセル 0 の場合は本体を評価せず離脱もしない、離脱の有無が上流の到達範囲ヘルパの条件と一致する、最悪ケース(本体が長い乗算でセル値 255)の実行量が監視倍率の範囲に収まり枯渇しない
  - 完了条件: 上記のテストが成功する
  - _Depends: 2.6_
  - _Boundary: emit_
  - _Requirements: 1.9, 3.1, 3.2, 4.1, 4.2, 4.4, 4.8, 6.5, 13.8_

  - 3 つの方式実行は同クレートの公開 API とし、命令数上限は 0 を含む任意の値を受け付ける(比較の入口である 3.2 の検証とは独立。差分テストの上限掃引が 0 から使う)。戻り値は観測値・単位・メトリクスを含む
  - コンパイル失敗は未対応(規模/入れ子)または失敗(方針違反/エンジン)へ、実行失敗は失敗(監視違反/出力量超過/不整合な途中状態/エンジン。不整合な途中状態はエンジンの失敗に分類)へ分類する。素朴は核の入力位置参照を含む完全な観測値を作る。WASM はホスト再生の命令数とモジュールのバイト数も返す
  - テストを書く: 各方式が代表プログラムで完走して観測値と単位(3 種)を返す、分類が正しい、素朴の観測値が核の完走実行と一致
  - 完了条件: 3 方式の呼び出しテストが成功し、WASM の単位が「なし」として返る

  - 要求(プログラム、入力、上限、追加方式、繰り返し回数)を検証し(上限 0 や最大超過、繰り返し範囲外はエラー)、基準(素朴)を常に先頭で実行し、選択された方式のみを同一条件で順に実行する。方式ごとの未対応/失敗は他方式の実行を妨げない
  - 繰り返しは時間予算で打ち切り、実際の回数を記録する。実行時間は中央値(偶数回は下側)とし、各回の観測が最初の回と異なる場合は「繰り返しの不一致」の失敗とする。時間は判定・成否に一切用いない
  - 比較の本体は、方式実行と時間予算を差し替えられる内部の入口として実装し、公開の比較関数はそれを実際の方式実行と実際の時間予算で呼ぶ。繰り返しの不一致と時間予算での打ち切りは、この内部入口を使う同モジュール内のテスト専用モジュールで検証する(遅いプログラムを使わない)
  - 各方式を基準と比較して判定(一致/不一致+項目)を付け、総合結果(全一致/不一致あり/未完了)を決定する。比較後に観測値を順次破棄してメモリを抑える
  - テストを書く: 基準が先頭で「基準」判定、方式選択の反映と重複の無視、繰り返しの中央値と回数、時間予算での打ち切り、観測が回ごとに異なる場合(テスト用の差し替え)の失敗分類、未対応が他方式を妨げない、同一要求の決定性(時間を除く)、不正な要求の拒否、比較の最大ステップが出力量上限以下であること
  - 完了条件: 比較のテストが成功し、実行時間の値がどのアサーションにも使われていない
