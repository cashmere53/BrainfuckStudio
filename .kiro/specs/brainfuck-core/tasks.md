  - 対応する `[` が無い `]` は走査中に最初に見つかった位置で閉じ括弧不一致を返し、解析終了時に残った `[` は最初に積まれた(最も早い)未解決位置で開き括弧不一致を返す。いずれも命令添字とソースバイトオフセットを含み、不一致なら実行可能なプログラムは返さない
  - 括弧対応表の参照として、括弧命令の対応先の問い合わせ(括弧以外・範囲外は該当なし)だけを公開し、対応先の対称性(対応先の対応先は自分自身)を保つ。表そのものは crate 内部専用の参照に留め(機械の実行だけが括弧命令の位置で読む)、括弧以外の未規定の値が外部から読めないようにする
  - `tests/parser.rs` に、単純・ネスト・並列の括弧の対応先、`]` 単独・`[]]` の閉じ括弧不一致(添字とオフセット)、`[[`・`[[]` の開き括弧不一致(最初の未解決位置)、不一致が複数ある場合の決定的な選択のテストを追加し、成功する。非 UTF-8 バイトの後ろの括弧エラーが入力バイト列上の実オフセットを示すテストも含める

  - ステップの判定順序を「停止済みか → ステップ上限に達していて未停止か → 命令実行」とする。停止済みは状態を変えず停止を返し、上限到達かつ未停止は追加命令を実行せず上限値と `pc` を含むステップ制限超過を返す。上限 0 の空プログラムは停止、非空は最初のステップでエラーとなる。エラー後に再度ステップしても同一エラーが返る
  - 命令は検証してから状態を更新し、成功時のみ実行数を 1 加算して `pc` を進める。コメント文字・スキップされた命令は数えない
  - 加算・減算は 8 ビットで折り返し(255 の次は 0、0 の前は 255)、現在セル以外を変更しない
  - ポインタ移動・入出力・ループの命令分岐は後続タスク(4.3 から 4.5)で実装するまでの仮の本体とし、このタスクのテストはそれらを実行するプログラムを使わない

  - _Depends: 4.1_
  - _Boundary: Machine_
