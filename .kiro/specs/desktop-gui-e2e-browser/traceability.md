## 手動スモーク 1〜15 の分類

## 備考

- **実アプリの確認の分担**: 実ウィンドウの ×(11.1〜11.3、11.5)、実際のリロード(11.6)、WebView2 の右クリックメニュー(11.7)、CSP の実効、13.3 の実 WebView2 での描画、1・3.1・4・9.3 の実 IPC での確認は、上の表にブラウザで自動化した部分を書いたうえで、実アプリでの確認を `desktop-gui-e2e-webview` が担う。10.1 と 12 の実ウィンドウでの最小サイズの強制は、同 spec も対象外で手動のまま。
- **8.6 のリロード検証**: CDP のキー入力では実際にはリロードされない。そのため `defaultPrevented` と `framenavigated` が 0 回であることで検証している。実際にリロードされないことの確認は webview。
- **編集可能判定**: `probes.ts` は、編集可能の判定で checkbox などの非テキストの `input` を「編集可能でない」とみなす。一方、アプリは `input` を全て編集可能とみなす。このため 5.10 のシナリオは text の `input` と `textarea` だけを使う。
- **並列度の高い環境**: `page.goto` が `ERR_ABORTED` や 30 秒のタイムアウトで不安定になることがある。単独の `--workers=1` なら通る(README「並列度と製品の不具合の記録」)。
- **`@perf`**: 通常の `chromium` プロジェクトからは除外され、別プロジェクト `perf` で実行する。閾値は 1,500 ms で、手動スモークの 1 秒より緩い。CI(`.github/workflows/e2e-browser.yml`)では `continue-on-error` で、失敗してもジョブ全体は失敗にならない。
- **14.1・14.2**: ブラウザのエミュレーションによる代替であり、OS の設定そのものの確認ではない。
- **フィクスチャの検査**: `smoke-01-startup.spec.ts` の「フィクスチャの検査」のテストは、スモーク 1〜15 の項目ではなく、E2E の基盤(閉じる要求・制御コマンド・ダイアログの後始末)の検査である。
