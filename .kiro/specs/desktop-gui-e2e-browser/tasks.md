# Implementation Plan

> 順序が依存を表す(タスク N は先行タスクに依存する)。`(P)` は直前の並列候補と競合しない独立タスク。依存の例外は `_Depends:_` で明示する。上流の desktop-gui が実装済み(`cargo test --workspace` と `apps/desktop` の `npm test` が成功する状態)であることを前提とする。
>
> 共通の決め事:
> - 製品のソース(`apps/desktop/src/**`、`apps/desktop/index.html`、`apps/desktop/vite.config.ts`、`apps/desktop/src-tauri/**`、`crates/*/src/**`。ただし本 spec が新設する `crates/brainfuck-e2e-bridge/` を除く)は変更しない。変更してよい設定・文書は design の「Modified Files」の一覧だけ(`brainfuck-gui-api` の `Cargo.toml` も変えない)
> - npm と node は `mise exec node@26 -- ...` で実行する。コマンドの打ち切りに `timeout` コマンドを使わない(待ち時間の上限が要る箇所は、テストランナーやブリッジの起動確認の仕組みで扱う)
> - 開発 PC では、新しく作られた実行ファイル(ブリッジ、テストの実行ファイル)がウイルス対策ソフトに止められて固まることがある。固まった場合は除外の設定を依頼し、新しい `CARGO_TARGET_DIR` で再ビルドする
> - E2E のシナリオで製品の不具合が見つかった場合は製品を直さず、該当テストを `test.fixme` にして注釈に現象と追跡先を書き、最終検証(8.1、8.2)で README と traceability に記録する

- [ ] 1. 基盤: ブリッジの骨格、E2E のツール設定、実行環境

- [ ] 1.1 テスト専用ブリッジの crate の骨格と行プロトコルを用意する
  - 新しい crate `crates/brainfuck-e2e-bridge`(`publish = false`、バイナリターゲット、`[lints] workspace = true`)を作る。依存は `brainfuck-gui-api`(path)、`serde`(derive)・`serde_json`、開発依存は `tempfile` だけとし、版はルートの `Cargo.lock` の既存の版に揃える(新しい外部 crate は足さない)。ルートの `Cargo.toml` は `members = ["crates/*"]` のため変えず、`brainfuck-gui-api` の `Cargo.toml` も変えない
  - 以降のタスクが同じファイルを奪い合わないよう、入口・プロトコル・サーバ・対応表・文書状態の各モジュールを先に宣言し、入口は空の受信ループで起動して終了できる状態にする
  - 2.x の並列タスクが先にコンパイルできるよう、共有の型の骨格を design の置き場どおりに先に宣言する: 文書状態の構造体(フィールドと既定値のみ。遷移は 2.1)、ブリッジの状態(サービスと文書状態)とダイアログの問い合わせ口のトレイト(対応表のモジュール)
  - Node からの要求とダイアログの返事、ブリッジからの応答とダイアログの問い合わせを、`type` で判別する 1 行 1 メッセージの JSON として読み書きする。成功の応答は値だけ、失敗の応答はエラーだけを持つ
  - 完了条件: `cargo test --workspace` でプロトコルの往復・不正な行の拒否・成功と失敗の応答の形のテストが通り、`cargo clippy --workspace --all-targets -- -D warnings` が成功し、`cargo tree -i brainfuck-e2e-bridge` に自身以外が現れない

- [x] 1.2 E2E のための依存とツールの範囲を整える

  - lint の除外にテストの出力ディレクトリとシムのビルド出力を加え、E2E のディレクトリに限ってフィクスチャの空の分割代入を許す
  - 単体テストの対象に E2E の補助モジュールの単体テストだけを加え、シナリオは含めない。ルートの `.gitignore` にテストの出力ディレクトリとシムのビルド出力を追記する(既存行は変えない)
  - 以降の各タスクは完了時に `npm run typecheck`(E2E を含む)を通すこと
  - 完了条件: `npm run typecheck`、`npm run lint`、`npm test`、`npm run build` が従来どおり成功し、`npx playwright --version` が 1.65 系を表示する。`e2e/` に型の誤りを一時的に書くと `npm run typecheck` は失敗し、`npm run build` は成功する
  - _Boundary: `apps/desktop/package.json`(devDependencies への `@playwright/test` の追加、scripts への `typecheck:app`・`e2e:*`・`e2e` の追加、`typecheck` と `build` の書き換えのみ)、`apps/desktop/package-lock.json`、`apps/desktop/tsconfig.e2e.json`(新規)、`apps/desktop/eslint.config.js`(`ignores` への追加と `e2e/**` の規則の追加のみ)、`apps/desktop/vitest.config.ts`(`include` への追加のみ)、ルートの `.gitignore`(追記のみ)_

- [ ] 2. 実際のバックエンドを通すブリッジ(Rust)

- [ ] 2.1 (P) 文書状態とファイルの読み書きを、アプリの Tauri 層と同じ規則で実装する
  - 文書状態(紐づけ先のパス・改行コード・未保存の旗)と、新規・開いた・保存した・未保存の記録の遷移を、アプリの文書状態と同じ既定値と規則で持つ。複製元と見直しの契機を冒頭に明記する
  - 読み込みは 1 MiB を超えるファイルを中身を読まずに上限超過で拒否し、それ以外は既存のデコード(置換と改行コードの記録)を呼ぶ。書き込みの失敗は既存の I/O エラーの形(パスを含まない)に写す
  - 完了条件: 一時ディレクトリを使う単体テストで、1 MiB 超の拒否、Shift_JIS の置換、CRLF の記録、存在しないディレクトリへの書き込みの I/O エラー、状態の遷移が確認できる
  - _Boundary: BridgeDocument_
  - _Requirements: 2.3, 7.3, 7.5, 7.6, 7.7_

- [ ] 2.2 (P) デバッガのコマンドと制御コマンドの対応表を実装する
  - デバッガの 9 コマンド(読み込み・開始・バッチ実行・Step・Reset・状態・テープ窓・ブレークポイント・Pause)を、要求の `args` を各要求 DTO へ読み取ってからサービスの同名の操作へ渡す。Pause はロックを取らない既存の操作を呼び、`null` を返す
  - 引数のキーが無い・形が違う・未知のフィールドは文字列のエラー、未知のコマンドも文字列のエラー、サービスのエラーは構造化エラーのまま返す
  - 対応するコマンド(現時点では `names.rs` の `COMMAND_NAMES` の全 14 件)の名前の一覧を公開の定数 `COMMANDS` として持つ(3.3 の契約テストが読む)。起動確認の制御コマンドを用意する
  - 完了条件: 単体テストで `examples/hello.bf` を読み込み・開始・実行した結果が pc 106・dp 6・実行数 906 になり、引数の不正・未知のコマンド・構造化エラーの各応答の形が確認できる
  - _Boundary: BridgeDispatch_
  - _Requirements: 2.1_

- [ ] 2.3 ファイル操作・閉じる判定のコマンドを対応表に加える
  - 新規・開く・保存・未保存の記録・終了の確定の 5 コマンドを、Tauri 層と同じ順序で実装する(開く: ダイアログ → 読み込み → 開いた。保存: 状態の読み取り → 変換の検査 → 紐づけ先が無いか別名のときだけダイアログ → 書き込み → 保存した)。ダイアログは問い合わせ口を通して受け取り、取消はそれぞれの取消の結果にする。終了の確定は何もしない
  - 閉じる要求の制御コマンドで、記録済みの未保存の旗から確認が必要かを返す(汚染されたロックでも旗の値で判定する)
  - 完了条件: スタブの問い合わせ口を使う単体テストで、開くの取消で文書が変わらない、変換できない本文の保存はダイアログを呼ばずに上限超過を返す、紐づけ済みの保存はダイアログを呼ばない、別名の保存は呼ぶ、CRLF のファイルを開いて保存すると CRLF のまま、閉じる判定が未保存の旗に従うことが確認できる
  - _Boundary: BridgeDispatch(`dispatch.rs` への 5 コマンドと閉じる判定の制御コマンドの追加のみ。`document.rs` は 2.1 の公開の形を使い、変えない)_
  - _Depends: 2.1, 2.2_
  - _Requirements: 2.3, 2.5, 2.6, 7.1, 7.2, 7.5_

- [ ] 2.4 受信ループと要求ごとの並行処理を実装し、入口から起動できるようにする
  - 共有の型(ブリッジの状態、ダイアログの問い合わせ口)は 1.1 の宣言を使い、ここでは受信ループ、要求ごとのスレッド、ダイアログの返事の振り分けと、問い合わせ口の実装だけを行う
  - 標準入力の各要求を別スレッドで処理し、応答を 1 行ずつロックして標準出力へ書く。標準出力にはプロトコルの行以外を書かず、解釈できない行は標準エラーへ記録して読み飛ばす
  - ダイアログが必要になった処理は問い合わせの行を書いて返事を待ち、受信ループが返事を要求の `id` で振り分ける。入力の終わりで受信ループは戻り、プロセスが終了する
  - 完了条件: 単体テストで、上限なしの `+[]` のバッチ実行中に送った Pause の応答がバッチの応答を待たずに返り、バッチが一時停止(キャンセル)で終わること、ダイアログの問い合わせと返事で保存が完了すること、複数の応答の行が混ざらないことが確認でき、`npm run e2e:bridge` でブリッジの実行ファイル(`target/debug/brainfuck-e2e-bridge[.exe]`)が作られる
  - _Boundary: BridgeServer, BridgeMain(`crates/brainfuck-e2e-bridge/src/server.rs` と `main.rs` の入口のみ。`dispatch.rs` の共有の型は 1.1 の宣言を使い、変えない)_
  - _Requirements: 2.1, 2.2, 2.3, 3.4_

- [ ] 2.5 (P) ブリッジが複製した Tauri 層の区間の指紋を固定する
  - `src-tauri` の `app_state.rs` の `DocumentState`(構造体・`Default`・`impl`)、`commands/files.rs` の開く・保存・新規・未保存の記録と読み書きの関数(design の一覧どおり)、`window.rs` の `close_requires_confirmation` の区間を読み、空白を正規化した SHA-256 をテストに固定した値と比べる Vitest の単体テストを書く
  - 区間の取り出し(宣言の行から対応する閉じ波括弧まで)は小さな関数に分けて単体テストを書く。区間が見つからない場合も失敗にする
  - 失敗の文面には、変わった区間の名前、新しい指紋、複製先(`crates/brainfuck-e2e-bridge/src/document.rs` / `dispatch.rs`)と、複製を合わせてブリッジの単体テストを通してから指紋を更新する手順を示す
  - 完了条件: `npm test` でこのテストが通り、比較の関数に区間を 1 文字変えた本文(テストの中の文字列。製品のソースは触らない)を渡すと、上の文面の失敗になることが単体テストで確認できる
  - _Boundary: TauriFingerprintTest(新規の `apps/desktop/e2e/support/bridge/tauriFingerprint.test.ts` のみ)_
  - _Depends: 1.2, 2.3_
  - _Requirements: 2.1, 2.3, 2.5_

  - 完了条件: 単体テストで、行の往復と不正な行の拒否、待ち行列の順序・予期しない要求の記録・保留と解放・残数が確認できる

- [x] 3.2 ブリッジのプロセスを管理するクライアントを実装する
  - ブリッジを起動し、要求に連番の `id` を付けて並行に送り、応答を `id` で対応づける。ダイアログの問い合わせには待ち行列の結果を返事として送る
  - 起動後に起動確認の制御コマンドで応答を待ち、上限時間(既定 30 秒、環境変数で変更可)を超えたら、ウイルス対策ソフトの除外・一時停止と新しい `CARGO_TARGET_DIR` を案内するメッセージで失敗する。実行ファイルが無い場合はパスと準備のコマンドを示す
  - プロセスが終了したら応答待ちの要求をすべて失敗にし、標準エラーの末尾を調査用に保持する。閉じるときは標準入力を閉じ、短い猶予の後に強制終了する
  - 完了条件: 偽の転送路(ストリームの組)を使う単体テストで、並行要求の対応づけ、ダイアログの返事、終了時の失敗、実行ファイルが無い場合と起動確認の失敗の文面が確認できる
  - _Boundary: BridgeClient(新規の `e2e/support/bridge/bridgeClient.ts` とその単体テストのみ。`protocol.ts`・`dialogQueue.ts` は 3.1 の公開の形を使い、変えない)_

- [x] 3.3 (P) ブリッジのコマンド一覧と Tauri の登録コマンドの一致を固定する
  - ブリッジの対応表のソース(`crates/brainfuck-e2e-bridge/src/dispatch.rs` の `COMMANDS`)からコマンド名の一覧を読み取り、登録の基準である `apps/desktop/src-tauri/src/commands/names.rs` の `COMMAND_NAMES` と集合で比べる単体テストを書く(既存のコマンド名の契約テストと同じく Rust のソースを読む方式)
  - ブリッジが扱わないコマンドは、テストの中の明示の除外一覧(コマンド名と理由)に置く(本 spec の時点では空)。`COMMANDS` と除外一覧の和が `COMMAND_NAMES` に等しく、両者が互いに素で、除外一覧に `COMMAND_NAMES` に無い名前が無いことを検査する。失敗の文面に、差のあるコマンド名と対処(ブリッジで対応する、または理由つきで除外一覧に入れる)を示す
  - 完了条件: `npm test` でこのテストが通り、比較の関数に `COMMAND_NAMES` にだけコマンドを足した入力・ブリッジにだけ足した入力・古い除外を残した入力を渡すと、それぞれ失敗することが単体テストで確認できる
  - _Boundary: CommandContractTest(新規の `e2e/support/bridge/commandContract.test.ts` のみ)_

- [x] 3.4 (P) ブラウザの IPC シムを実装し、単独でビルドできるようにする

  - 製品のスクリプトより前に IPC の模擬(イベントの模擬を有効)を設定し、イベント以外のすべての呼び出しを公開された転送関数へ渡す。閉じる要求のイベントを発火する操作口を公開する。イベント名はフロントの定数を使う
  - シムを製品のビルド設定とは独立の設定で、1 ファイルのスクリプトとしてビルドする
