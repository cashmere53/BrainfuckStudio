# Implementation Plan

> 順序が依存を表す(タスク N は先行タスクに依存する)。`(P)` は直前の並列候補と競合しない独立タスク。依存の例外は `_Depends:_` で明示する。
>
> 前提: 上流の `desktop-gui-e2e-browser` のうち、E2E の依存とツール設定(同 spec のタスク 1.2)、Playwright の設定と準備物の確認(1.3)、ページオブジェクト(4.1)、見た目の補助(4.3)、既定動作の観測(4.5)が実装済みであること。未実装なら本 spec の実装を始めない。
>
> 共通の決め事:
> - 製品のソース・設定(`apps/desktop/src/**`、`apps/desktop/index.html`、`apps/desktop/vite.config.ts`、`apps/desktop/src-tauri/**`、`crates/*/src/**`)は変更しない。ブラウザのスイートの部品と設定も変更しない。変更してよい既存ファイルは design の「Modified Files」の 3 つだけ(`playwright.config.ts` は import 1 行と `projects` の展開 1 行のみ)
> - ブラウザのスイートの部品に変更が必要になった場合は、ここで直さず、本 spec の design の「ブラウザの spec への変更」に書き、ブラウザの spec へ差し戻す
> - npm と node は `mise exec node@26 -- ...` で実行する。コマンドの打ち切りに `timeout` コマンドを使わない(待ち時間の上限は起動確認やテストランナーの仕組みで扱う)
> - 開発 PC では、新しく作られた実行ファイル(実アプリの debug ビルド)が Avast に止められて固まることがある。固まった場合は除外の設定を依頼し、新しい `CARGO_TARGET_DIR` で再ビルドする(`E2E_APP_BIN` で実行ファイルを指定できる)。固まったプロセスは再起動まで消えないことがある
> - E2E の実行中はキーボードとマウスを操作しない(OS の入力と前面化を使うため)。同じ PC で複数の E2E を同時に実行しない(`(P)` のタスクでも、コードは並行して書けるが、実アプリを使う確認は 1 つずつ行う)
> - シナリオのタスクの確認は、準備を済ませた上で `npm run e2e:webview:run -- <ファイル名>` で対象のファイルだけを実行する(全体の `npm run e2e:webview` は最終検証で行う)
> - webview の単体テスト(`e2e/support/webview/*.test.ts`)は、上流と同じく各ファイルの先頭に `// @vitest-environment node` を置く(Vitest の既定は jsdom と `src/test/setup.ts`。`appProcess`・`cspProbe`(`node:http`)・`windowsHost` などは Node の API を使う)
> - E2E で製品の不具合が見つかった場合は製品を直さず、該当テストを `test.fixme` にして注釈に現象と追跡先を書き、最終検証(5.1、5.2)で README と traceability に記録する

- [x] 1.5 実アプリのプロセスの管理を実装する
  - 空きポートの取得、継承した WebView2 の環境変数を除いて、追加の引数(デバッグ用の口 `--remote-debugging-port=<port>` だけ。アプリの既定の追加引数は環境変数に写さない)と利用者データのフォルダの 2 つだけを設定する環境の組み立て、シェルを介さない起動、標準出力・標準エラーの末尾の保持を実装する
  - 追加の引数の環境変数はアプリの指定に追加される(置き換えない)ことを、通常の起動とテストの起動のそれぞれで WebView2 のブラウザプロセス(アプリの子)のコマンドラインを OS から取得して確かめる。比較は重複を除いた実効のスイッチの集合で行い、比較の結果は最終検証で README に記録するため控えておく。想定と違えば(アプリの既定の引数が消えるなど)design を更新してから進める
  - CDP の口のバージョン情報が応答するまで待ち、プロセスの早期終了・実行ファイルなし・上限時間の超過(既定 60 秒、環境変数で変更可)を理由つきのエラーにする。上限超過の文面でウイルス対策ソフトの除外・一時停止、新しい `CARGO_TARGET_DIR`、再起動を案内する
  - 終了は、動いていればプロセスツリーごと終わらせて終了を待ち、利用者データのフォルダを再試行つきで削除し、削除の成否を返す(投げない)

  - _Boundary: AppLauncher_

- [ ] 2. 観測の補助とフィクスチャ

- [x] 2.1 (P) 実アプリのページの観測の補助を実装する
  - IPC の観測を 2 つの方式で提供する。既定の方式は、IPC の要求の URL からコマンド名を取り出す純粋関数でページのネットワーク要求を購読する。切り替え先の方式は、ページ内の Tauri の内部の `invoke` を包んで呼び出しと完了を記録する(製品は変えない)。どちらも、観測したコマンドの一覧と「待ち受けを確定した以後に完了した特定のコマンドの応答」を待つ手段を同じ形で提供し、方式は 1 つの定数で選ぶ(2.3 で確定する)
  - ページ内で閉じる要求のイベントをもう 1 つ購読して受信回数を数える補助(イベント名はフロントの定数を使う)、ページに一意の目印を置いてメインフレームの遷移を数える補助、陽性対照のためにキー入力と右クリックのアプリの抑止を無効にする補助を書く
  - 完了条件: コマンド名の取り出し(IPC の URL、エンコードされた名前、対象外の URL)と、`invoke` の包み込み(偽の `invoke` で、呼び出しの名前と完了の回数が記録され、元の結果と例外がそのまま返る)の単体テストが `npm test` で通り、型検査と lint が通る
  - _Boundary: AppProbes_
  - _Requirements: 4.2, 5.4, 5.6, 6.1, 6.2, 6.4_

- [x] 2.2 (P) CSP の検証の補助を実装する
  - ページの CSP の違反(有効なディレクティブと拒否された URI)を記録・読み出す補助と、`127.0.0.1` の空きポートで受けた要求を数えるだけの外部の受け口のサーバを書く
  - 完了条件: 受け口が要求を数えて閉じられることの単体テストが `npm test` で通り、型検査と lint が通る
  - _Boundary: CspProbe_
  - _Requirements: 7.1, 7.2, 7.3_

- [ ] 2.3 webview のフィクスチャを実装し、起動のシナリオで全経路を通す
  - シナリオごとに実アプリを起動して CDP で接続し、既定のコンテキストから配信オリジンのページを特定してエディタの表示を待ち、ページ・上流のページオブジェクト・pid に束ねた OS の窓口・接続直後からの IPC の観測を渡す
  - 後始末で、失敗ならスクリーンショットと出力の末尾を添付し、WebView2 の版を注釈し、接続を切ってプロセスを終了させ、フォルダの削除の失敗を警告の注釈にする。組み込みの `page`・`context`・`browser` を使わない
  - 観測の補助(2.1)を実アプリで一度通す: 閉じる要求の受信の計数の設置が失敗しないこと、ナビゲーションの目印が残っていると読めること、接続後にエディタを編集して `set_document_dirty` の要求と応答が観測されること(起動時の IPC は `plugin:event|listen` だけで CDP の接続より前に終わり、`load_source` は Run の開始からだけ呼ばれるため、起動時の要求は観測の対象にしない)。失敗は 2.1 に差し戻す
  - IPC の観測の方式の判断点: 既定のネットワーク要求の方式で `set_document_dirty` が観測できなければ、方式の定数を `invoke` の包み込みに切り替えて同じ確認をやり直し、判断の結果(どちらの方式で観測できたか)を research.md に記録する。どちらでも観測できなければ 3.1・3.3 を進めず、design を見直す
  - 起動のシナリオ(スモーク 1)を書く: OS のウィンドウのタイトル、エディタの内容がリポジトリの `examples/hello.bf` と一致、「無題」、「未開始」、Run・Step の有効と Pause・Reset の無効
  - 本タスクはフィクスチャと起動のシナリオをつなぐ統合タスクである
  - 完了条件: Windows で `npm run e2e:webview` の起動のシナリオが成功し、観測の補助の確認(接続後の編集での `set_document_dirty` の観測を含む)が通り、IPC の観測の方式が確定して research.md に記録され、検証を一時的に失敗させるとスクリーンショットと出力の末尾が結果に残り、実行後に実アプリのプロセスと一時フォルダが残らない
  - _Boundary: WebviewFixtures, Smoke01(AppProbes は方式の定数 `IPC_OBSERVATION_MODE` の値の変更だけを許す)_
  - _Depends: 1.5, 2.1_
  - _Requirements: 1.2, 1.6, 1.8, 1.9, 1.10, 2.1, 3.2, 4.1_
