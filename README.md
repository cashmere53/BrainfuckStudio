# BrainfuckStudio

BrainfuckStudio は、Brainfuck を正確に実行し、実行過程(ソース、命令位置、テープ、出力)を観察・比較するための学習用スタジオです。現時点では次の 2 つの crate を含みます。

- `crates/brainfuck-core` — Brainfuck の解析と実行を行う値型・状態機械(I/O を持たないライブラリ)
- `crates/brainfuck-cli` — `brainfuck-core` をファイル、標準入出力、終了コードの境界から利用するコマンドラインツール

## 検証手順

リポジトリのルートで次のコマンドを実行します。

```sh
cargo test --workspace
cargo run -p brainfuck-cli -- examples/hello.bf
```

2 つ目のコマンドは、標準出力に `Hello World!` と改行を出力し、終了コード 0 で終了します。`examples/hello.bf` は `--input` を指定せず入力命令も含まないため、標準入力は読まれず、端末で入力待ちになることはありません。

## 使用方法

```sh
brainfuck-cli [OPTIONS] <PROGRAM>
```

`<PROGRAM>` には Brainfuck のソースファイルを 1 つ指定します。オプションは `--name value` と `--name=value` のどちらの形式でも指定でき、`<PROGRAM>` の前後どちらに置いても構いません。

```sh
cargo run -p brainfuck-cli -- examples/hello.bf
cargo run -p brainfuck-cli -- --max-steps=1000 examples/hello.bf
cargo run -p brainfuck-cli -- examples/hello.bf --input data.bin --dump-state
```

## オプション

| オプション | 値 | 説明 |
| --- | --- | --- |
| `--input <PATH>` | ファイルパス | 入力を標準入力ではなく `PATH` のファイルから読む |
| `--max-steps <N>` | 非負整数 | 実行する命令数の上限を `N` にする。上限に達すると終了コード 3 で停止する |
| `--no-step-limit` | なし | 命令数の上限を無効にする。`--max-steps` と併用できない |
| `--dump-state` | なし | 実行後(正常終了・実行エラーのどちらでも)に `pc`、`dp`、`steps` を標準エラーへ出力する |
| `--help` | なし | 使用方法を標準エラーへ出力し、終了コード 0 で終了する |

## 命令数上限

既定の命令数上限は **10,000,000** です。終了しないプログラム(例: `+[]`)を誤って実行しても、上限に達した時点で終了コード 3 で停止します。上限は `--max-steps <N>` で変更でき、`--no-step-limit` で無効にできます。

## 終了コード

| 終了コード | 意味 |
| --- | --- |
| 0 | 正常終了 |
| 2 | 使用方法の誤り、または解析エラー(括弧の不一致) |
| 3 | 実行エラー(データポインタの範囲外、命令数上限への到達など) |
| 4 | 入出力エラー(プログラムファイル、入力ファイル、標準入力、標準出力のいずれかの失敗) |

複数の失敗が同時に起きた場合は、処理の段の順序(引数 → ソース読込 → 解析 → 入力取得 → 実行 → 出力)で最初に失敗した段の分類を終了コードとします。ただし標準出力への書き込みに失敗した場合は、実行エラーの有無にかかわらず終了コード 4 になります。

## 標準出力と標準エラー

- **標準出力**: Brainfuck プログラムの出力バイト列だけを書き出します。診断や状態表示は含みません。
- **標準エラー**: 診断メッセージ、`--dump-state` の状態表示、`--help` の使用方法を書き出します。

実行エラーがあった場合は、それまでに出力された部分出力が先に標準出力へ書き出され、その後で診断が標準エラーへ書かれます。

### 出力の扱いに関する注意

- **端末へ直接表示する場合**: Brainfuck の出力はバイト列であり、UTF-8 として正しくないバイトを含むことがあります。その場合、OS や端末の文字コード処理によって表示できない、または別の文字に置き換わることがあります。
- **ファイルやパイプへリダイレクトする場合**: バイト列はそのまま保存されるため、出力を正確に取得できます。例: `cargo run -p brainfuck-cli -- prog.bf > out.bin`
- **`--no-step-limit` を使う場合**: 終了しないプログラムは停止しないため、出力は実行終了後にまとめて書き出されず、CLI プロセスのメモリに溜まり続けます。出力先のファイルやパイプへは何も書かれない点に注意し、メモリを使い切るおそれがあるため、必要な場合のみ使用してください。
- **標準出力への書き込みに失敗した場合**: 出力先が閉じられているなど、標準出力への書き込みが失敗すると、CLI は終了コード 4 で終了します。端末への直接表示で書き込みが失敗するかどうかは、OS や端末の環境によって異なる場合があります。

## 標準入力

プログラム中に入力命令 `,` が含まれ、かつ `--input` が指定されていない場合にのみ、標準入力を読みます。入力命令を含まないプログラムや `--input` を指定した場合は、標準入力は読まれません。

入力が終端に達したあとの `,` は、セルに 0 を書き込みます(EOF = 0)。

```sh
echo -n A | cargo run -p brainfuck-cli -- prog.bf
cargo run -p brainfuck-cli -- prog.bf --input data.bin
```
