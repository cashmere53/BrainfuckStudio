# 比較画面(コンパイル実行方式の比較)

デバッガ画面で編集中のソース・入力・命令数上限を、3 つの実行方式で同じ条件で実行し、結果が一致するかを確かめる「比較」画面の利用者向け文書です。
方式の位置づけ、実行数の定義、比較用の上限値、安全方針、既知の制約、手動確認手順を記載します。

> **注意**: 比較の観測値は、素朴インタプリタを唯一の基準(オラクル)として完全状態を照合した結果です。実行時間は観察の対象であり、最適化やコンパイルの正しさの証明でも性能の保証でもありません(後述「時間の読み方」)。

## 1. 比較画面の使い方

1. アプリ上部の画面タブで **「比較」** を選びます。デバッガ画面と比較画面は同じ Workspace を共有しており、デバッガ画面で編集中の **ソース(未保存の編集内容を含む)**、**入力**、**命令数上限** をそのまま使います。
2. 比較画面で次を指定します。
   - **「比較する方式」**: 「最適化インタプリタ」「WASM コンパイル実行」のチェックボックス(既定ではどちらもオン)。素朴インタプリタは基準として常に実行され、選択肢には出ません。
   - **「繰り返し回数(1〜5)」**: 既定は 3 回。1〜5 の整数で指定します。
3. **「比較を実行」** ボタンを押します。
4. 結果は次の形で表示されます。
   - **総合結果の帯**: 「すべて一致」「不一致あり」「未対応または失敗あり」のいずれか(記号 ✓ / ✗ / △ を併記)。
   - **方式ごとの結果表**(列: 方式、判定、準備時間、実行時間、換算実行数、方式固有の単位、終了状態、成果物)。素朴インタプリタの行が基準です。
   - 各方式の行の直後にある「○○の終了状態の詳細」を開くと、終了状態の詳細を見られます。
   - 結果表の有無にかかわらず、実行数の凡例と免責文は常に表示されます。
5. 比較の実行中は「実行中です…」と表示され、「比較を実行」は無効になります。比較の結果と実行状態は画面の切り替えで保持されます。実行中に別のタブへ移っても、比較タブに戻ると結果(または実行中の表示)が表示されます。比較はデバッガ画面のセッション・実行状態・表示内容を変更しません。
6. デバッガ画面でソース・入力・命令数上限を編集してから比較タブへ戻ると、「条件が変更されています(再実行してください)」と表示されます。表示中の結果は古い結果であるため、「比較を実行」で再実行してください(手順は「8.9」)。

### 入力の条件(実行できない場合)

次のいずれかの場合、「比較を実行」は無効になり、理由が実行ボタンの近くに表示されます。

| 状態 | 表示される理由 |
| --- | --- |
| 「命令数上限」で「上限なし」を選んでいる | 上限なしでは比較できません。上限を指定してください |
| 上限が 1 以上の整数でない | 命令数の上限は 1 以上の整数で指定してください |
| 上限が比較用の最大値(50,000,000)を超える | 命令数の上限は 50000000 以下で指定してください |
| 入力が 16 進として不正 | 入力が正しくありません。16 進の表記を確認してください |
| ソースまたは入力が 1 MiB を超える | ソースが 1 MiB を超えているため比較できません / 入力が 1 MiB を超えているため比較できません |
| 繰り返し回数が 1〜5 の範囲外 | 繰り返し回数は 1 以上 5 以下で指定してください |

## 2. 比較できる方式

| 方式 | 画面の表記 | 内容 |
| --- | --- | --- |
| 素朴インタプリタ | 素朴インタプリタ | `brainfuck-core` の命令単位の実行器。**基準**であり、常に実行されます。 |
| 最適化インタプリタ | 最適化インタプリタ | `brainfuck-optimized` の中間表現(IR)を実行します。連続命令やループの一部をまとめて実行します。 |
| WASM コンパイル実行 | WASM コンパイル実行 | 最適化 IR から WebAssembly を生成し、隔離された実行器(`wasmi`)で実行します。採用方式です(後述「4. 採用方式: WASM」)。 |

各方式の結果は、基準の素朴インタプリタと次の完全状態で照合されます。

- 出力のバイト列
- 最終テープ(30,000 セル全体)
- 終了の種類(正常停止・ポインタ範囲外・命令数上限超過)とエラー値
- データポインタ、入力読取位置、`pc`(命令添字)
- 素朴換算の実行数

判定は次のいずれかです。

- **基準**: 素朴インタプリタの行。
- **一致 ✓**: 基準と完全に一致した。
- **不一致 ✗(項目)**: 一致しなかった。不一致の観測項目(終了の種類、エラー値、pc、dp、現在セル、実行数、入力位置、出力、テープ)が併記されます。
- **未対応**: 方式のコンパイルが上限を超えたため実行されていない(後述「6. 既知の制約」)。
- **失敗**: 方式の実行が資源の制限で打ち切られた、または方式の内部エラーが起きた。

未対応・失敗は「不一致」とは別の表示になります。ある方式が未対応・失敗でも、他の方式の結果は表示されます。

## 3. 各方式の実行数の定義

比較画面では、実行数に関わる値が 2 種類あります。混同しないよう、表の列名と凡例を確認してください。

### 3.1 素朴実装換算の実行数(「換算実行数」列)

- 素朴インタプリタが同じ実行で数える命令数です。
- **全方式で同じ定義・同じ値**になり、方式間の一致判定の対象です。
- 命令数の上限(後述 5.1)は、この値に対して適用されます。
- 実行が途中で止まった場合も、同じ時点で素朴インタプリタが数える値と一致します。

### 3.2 方式固有の単位(「方式固有の単位」列)

| 方式 | 表示 | 意味 |
| --- | --- | --- |
| 素朴インタプリタ | 実行命令数 N | 実際に実行した命令の数。 |
| 最適化インタプリタ | IR 操作回数 N | 最適化 IR の操作(連続命令やループを 1 回と数える)の実行回数。実行命令数とは異なる値になります。 |
| WASM コンパイル実行 | なし | 方式固有の単位を数えません。値の欠落ではなく、「なし」という明示の状態です。 |

方式固有の単位は表示のみで、一致判定には使いません。

## 4. 採用方式: WASM

### 4.1 概要

- **生成**: 最適化 IR から WebAssembly のバイナリを生成します(`wasm-encoder`)。同じ IR からは毎回同じバイト列が生成されます。
- **監査**: 生成後、`wasmparser` で生成物の方針を検査します。1 つでも方針から外れていれば拒否し、実行しません。
- **実行**: `wasmi` のインタプリタで実行します。`wasmi` は機械語を生成しません。
- **離脱後の再生**: 生成コードが「定数の上限を超える」「範囲外に出る」などの操作に当たると、状態を変更する前にそこで離脱します。残りの実行は上流の `brainfuck-optimized` の再生機能(素朴の意味論を実装したもの)が行います。WASM 側に素朴の意味論の複製はありません。

### 4.2 安全方針

生成物は次の範囲に限られます。

- **外部との接点は入出力の 2 関数のみ**: import は `bf.read`(入力 1 バイト取得)と `bf.write`(出力 1 バイト送出)だけです。WASI は使いません。export は `run`(実行)と `memory`(テープ)だけです。
- **ファイル・ネットワーク・プロセス・環境変数・時刻・乱数へのアクセスは持ちません。**
- **メモリは 1 ページ(64 KiB)固定**で、拡張はできません(テープは先頭 30,000 バイト)。
- **テーブル・グローバル・start 関数は持ちません。** 浮動小数点命令や間接呼び出しも含みません。
- **外部から WASM を読み込む経路はありません。** 生成するのは Brainfuck ソースから本機能が作った生成物のみです。
- **出力量は 64 MiB まで**です。超えると実行を中断し、「失敗」として報告します。
- **実行量は二重に監視します。** 命令数の上限(厳密)と燃料(第二の防御)の 2 つです。燃料は「上限 × 64 + 1024 + 生成物のバイト数」で与えられ、尽きると「失敗」になります。
- `unsafe` は使いません(クレートの属性とワークスペースの lint の両方で禁止)。

### 4.3 資源の上限

| 項目 | 値 | 超えた場合 |
| --- | --- | --- |
| 生成モジュールのサイズ | 8 MiB | 未対応 |
| ループの入れ子の深さ | 256 | 未対応 |
| 出力量 | 64 MiB | 失敗 |
| 命令数の上限(比較) | 50,000,000 | 入力欄で拒否(実行不可) |
| 繰り返し回数 | 1〜5(既定 3) | 入力欄で拒否(実行不可) |
| ソース・入力のサイズ | 各 1 MiB | 入力欄で拒否(実行不可) |

## 5. 比較用の上限値

### 5.1 命令数の上限

- 比較の各方式は、**素朴換算の実行数**で最大 **50,000,000** まで実行します。
- 上限は必須です。「上限なし」では比較できません。
- 上限は 1 以上の整数で指定します。上限 0 は比較できません。
- 上限が素朴インタプリタの必要数より 1 小さいと「命令数上限超過」になり、上限と同数の命令まで実行した時点で中断します。上限がちょうど必要数と等しいと正常停止になります。

### 5.2 繰り返し回数と時間予算

- 繰り返し回数は 1〜5 で、既定は 3 です。
- 各方式の実行時間は、繰り返した結果の**中央値**(偶数回のときは下側の値)で表示されます。
- 繰り返しは **2 秒の時間予算**で打ち切られます。打ち切られた場合、表の「○ 回の中央値」に**実際に行った回数**が表示されます。
- 繰り返しの各回の結果(実行数、出力、テープなど)が最初の回と異なった場合は、その方式は「失敗(繰り返しの結果が一致しなかった)」として報告されます。

## 6. 既知の制約

### 6.1 WASM が未対応となる条件

次のいずれかに当たる場合、WASM 方式は実行されず、結果表に「未対応」と理由が表示されます。他の方式の結果は表示されます。

- **ループの入れ子が 256 を超える**(表示: 「ループの入れ子が深すぎるため未対応」)。
- **生成モジュールが 8 MiB を超える**、または生成コードの数値が表現範囲を超える(表示: 「モジュールが大きすぎるため未対応」)。

未対応は「不一致」ではありません。総合結果は「未対応または失敗あり」になります。

### 6.2 解析エラー

ソースの括弧が対応しない場合、どの方式も実行されず、「解析エラー」として種類・命令添字・位置(行と列)が表示されます。結果表は表示されません。種類は「対応する閉じ括弧がない開き括弧」「対応する開き括弧がない閉じ括弧」のいずれかです。

### 6.3 時間の読み方

- 実行時間は**観察の対象**です。方式の良し悪し、正しさ、成否の判定には使いません。
- 実行器 `wasmi` はインタプリタであるため、パターンを主体としないプログラムでは、素朴インタプリタより遅くなる場合があります。
- 準備時間は方式ごとに測ります。素朴インタプリタは準備を持たないため「準備なし」と表示されます。
- 実行時間の表示に、結果の整形や画面表示の時間は含みません。

> 画面に表示される免責文: 「実行時間は観察の対象であり、性能や正しさの保証ではありません」

## 7. クレート構成

比較機能は、デバッガ用 API のクレートとは別のクレートに分けています。

| クレート | 役割 | 主な依存 |
| --- | --- | --- |
| `brainfuck-core` | 素朴インタプリタと解析 | (なし) |
| `brainfuck-optimized` | 最適化 IR と最適化インタプリタ | `brainfuck-core` |
| `brainfuck-wasm` | WASM の生成・監査・隔離実行 | `brainfuck-core`、`brainfuck-optimized`、`wasm-encoder`、`wasmparser`、`wasmi` |
| `brainfuck-compare` | 観測・方式実行・比較・メトリクス(UI と JSON に依存しない) | `brainfuck-core`、`brainfuck-optimized`、`brainfuck-wasm` |
| `brainfuck-compare-api` | 比較の DTO とサービス(比較画面用) | `brainfuck-compare`、`brainfuck-gui-api`、`brainfuck-core` |
| `brainfuck-gui-api` | デバッガ用 API | `brainfuck-core` のみ(比較・WASM の依存は持たない) |

- デバッガ用 API(`brainfuck-gui-api`)は、比較・WASM・実行エンジンに関わる依存を持ち込みません。そのため、デバッガ用 API のビルドとテストは比較機能の有無に影響されません。
- アプリ側では、`apps/desktop/src-tauri` が `brainfuck-compare-api` を依存に加え、比較のコマンド(`get_comparison_info` と `run_comparison`)を提供します。フロントの比較画面は `apps/desktop/src/comparison/` にあります。

## 8. 手動確認手順

以下は、アプリ(Tauri)で比較機能が動く状態を前提とした手順です。画面の文言・ボタン名は、現在の実装(`ComparisonScreen.tsx`、`components/MethodOptions.tsx`、`domain/comparisonFormat.ts`)のとおりです。

> **未実施**: 実機での手動確認は、まだ行っていません(本機能のリリース前検証で実施します)。以下の期待値は仕様と実装から導いたものです。

### 8.1 準備

1. アプリを起動し、画面タブで **「デバッガ」** を選びます。
2. **「ソース」** の欄に、リポジトリの `examples/hello.bf` の内容を貼り付けます。
3. **「入力」** の欄は空のままにします。
4. **「命令数上限」** の欄に `1000000` と入力し、**「上限なし」** のチェックは外したままにします。

### 8.2 hello での 3 方式一致(換算実行数 906)

1. 画面タブで **「比較」** を選びます。
2. **「比較する方式」** で「最適化インタプリタ」と「WASM コンパイル実行」がオンになっていることを確認します。**「繰り返し回数(1〜5)」** は既定の `3` のままにします。
3. **「比較を実行」** を押します。
4. 次を確認します。
   - 総合結果の帯が **「✓ すべて一致」** になる。
   - 結果表の 3 行(素朴インタプリタ、最適化インタプリタ、WASM コンパイル実行)の判定が、素朴は **「基準」**、他の 2 方式は **「一致 ✓」** になる。
   - 3 行すべての **「換算実行数」** が **906** になる。
   - WASM の行の **「方式固有の単位」** が **「なし」** になる(空欄や「—」ではないこと)。
   - 最適化の行の **「方式固有の単位」** が **「IR 操作回数 151」** になる(換算実行数 906 より少ない値)。

### 8.3 乗算ループでの方式固有の単位の違い

1. 「デバッガ」画面の **「ソース」** の欄を次の内容に置き換えます(8×8 = 64 を出力し、`@` と表示されます)。

   ```
   ++++++++[>++++++++<-]>.
   ```

2. 「比較」画面で **「比較を実行」** を押します。
3. 次を確認します。
   - 3 方式とも判定が一致し、総合結果が **「✓ すべて一致」** になる。
   - 3 方式とも **「換算実行数」** が **107** になる。
   - 最適化の行の **「方式固有の単位」** が **「IR 操作回数 4」** になる(換算実行数 107 とは異なる値)。
   - WASM の行の **「方式固有の単位」** が **「なし」** になる。
   - 素朴の行の **「方式固有の単位」** が **「実行命令数 N」** と表示される(素朴の方式固有の単位は、方式が実際に数えた命令数)。

   参考: 同じソースを命令数上限 `5` で実行すると、3 方式とも **「命令数上限超過」** になります(手順は後述の 8.4)。

### 8.4 上限超過が全方式で同一に表示されること

1. 「デバッガ」画面の **「ソース」** に `++++++++[>++++++++<-]>.` を入れたまま、**「命令数上限」** を `5` にします。
2. 「比較」画面で **「比較を実行」** を押します。
3. 次を確認します。
   - 3 方式の **「終了状態」** がすべて **「命令数上限超過(上限: 5, pc: N)」** で、同じ文言・同じ `pc` の値になる。
   - 素朴は判定が **「基準」**、最適化と WASM は **「一致 ✓」** になり、総合結果が **「✓ すべて一致」** になる。
   - 終了状態の詳細(各行の「○○の終了状態の詳細」)を開いても 3 方式の内容が同じである。

### 8.5 範囲外が全方式で同一に表示されること

1. 「デバッガ」画面の **「ソース」** を `<` に置き換え、**「命令数上限」** を `100` にします。
2. 「比較」画面で **「比較を実行」** を押します。
3. 次を確認します。
   - 3 方式とも **「終了状態」** が **「ポインタ範囲外(pc: …, dp: …, 左へ移動)」** で、同じ文言になる。
   - 判定が 3 方式とも一致し、総合結果が **「✓ すべて一致」** になる。

### 8.6 解析エラー

1. 「デバッガ」画面の **「ソース」** を `+[` に置き換えます。
2. 「比較」画面で **「比較を実行」** を押します。
3. 次を確認します。
   - 結果表は表示されず、**「解析エラー」** の見出しと次の内容が表示される。
     - 種類: 対応する閉じ括弧がない開き括弧
     - 命令添字: (数値)
     - 位置: 行 (数値)・列 (数値)
   - どの方式も実行されていないため、結果表は出ない。

### 8.7 実行が無効になる条件

1. 「デバッガ」画面の **「上限なし」** にチェックを入れます(「命令数上限」の欄は入力できなくなります)。
2. 「比較」画面で、**「比較を実行」** が押せない(無効)ことを確認します。実行ボタンの近くに **「上限なしでは比較できません。上限を指定してください」** と表示されます。
3. 「デバッガ」画面で **「上限なし」** を外し、**「命令数上限」** を `50000001` と入力します。
4. 「比較」画面で、実行が無効になり **「命令数の上限は 50000000 以下で指定してください」** と表示されることを確認します。
5. 「比較」画面の **「繰り返し回数」** を `0` または `6` にすると、実行が無効になり **「繰り返し回数は 1 以上 5 以下で指定してください」** と表示されることを確認します。

### 8.8 WASM の未対応表示(入れ子超過)

ループの入れ子が 256 を超える合成プログラムを使います。`+` の後に `[` を 257 個、`.-` を入れ、`]` を 257 個続けたプログラムです。PowerShell では次のコマンドで生成できます(517 文字)。

```powershell
'+' + ('[' * 257) + '.-' + (']' * 257)
```

1. 生成した文字列を「デバッガ」画面の **「ソース」** に貼り付け、**「命令数上限」** を `1000` にします。
2. 「比較」画面で **「比較を実行」** を押します。
3. 次を確認します。
   - 素朴インタプリタと最適化インタプリタは **「正常停止」** になり、判定が一致する(「基準」「一致 ✓」)。
   - WASM コンパイル実行の行の判定が **「未対応」** になり、理由として **「ループの入れ子が深すぎるため未対応」** が表示される。WASM の結果の数値は表示されない(「—」)。
   - 総合結果の帯が **「△ 未対応または失敗あり」** になる(不一致ではない)。

### 8.9 画面切替での結果の保持と古い結果の表示

1. 「デバッガ」画面の **「ソース」** を `++++++++[>++++++++<-]>.` にし、**「命令数上限」** を `1000` にします。
2. 「比較」画面で **「比較を実行」** を押し、結果が表示されるまで待ちます。
3. **「デバッガ」** のタブへ移り、**「ソース」** の末尾に 1 文字(例: スペース)を入力します。
4. **「比較」** のタブへ戻ります。
5. 次を確認します。
   - 直前の比較結果が残っている(画面切替で結果は消えない)。
   - **「条件が変更されています(再実行してください)」** が表示される。
6. 「デバッガ」タブで、追加した 1 文字を削除して内容を元に戻し、「比較」タブへ戻ります。「条件が変更されています」の表示が消えることを確認します。
7. 実行中の保持を確認する: 「比較」タブで「比較を実行」を押し、「実行中です…」の表示中に「デバッガ」タブへ移ってから「比較」タブへ戻ります。比較の結果(または実行中の表示)が表示されることを確認します。
